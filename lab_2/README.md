# Лабораторная работа №2. Вариант 6

## Задание

Перемножить две матрицы комплексных чисел двумя способами:

1. последовательно;
2. параллельно с использованием POSIX Threads (`pthread`).

Программа измеряет время обеих версий, проверяет совпадение результатов,
вычисляет ускорение и эффективность.

Матрицы не обязаны быть квадратными. Для умножения число столбцов матрицы
`A` должно совпадать с числом строк матрицы `B`:

```text
A[M x N] * B[N x K] = C[M x K]
```

## Файлы проекта

- `main.c` — чтение параметров, измерение времени и вывод результатов;
- `matrix.c` — создание, заполнение и последовательное умножение матриц;
- `parallel.c` — параллельное умножение с помощью `pthread`;
- `matrix.h` — структуры и объявления функций;
- `Makefile` — сборка проекта.

## Сборка

```bash
make
```

После сборки появляется исполняемый файл `main`.

Удаление исполняемого файла:

```bash
make clean
```

## Запуск

```bash
./main -m M -n N -k K -t ПОТОКИ
```

Флаги должны быть записаны строчными буквами и именно в указанном порядке:

- `-m` — число строк матрицы `A`;
- `-n` — число столбцов `A` и одновременно число строк `B`;
- `-k` — число столбцов матрицы `B`;
- `-t` — число создаваемых потоков.

Пример для квадратных матриц и четырёх потоков:

```bash
./main -m 1024 -n 1024 -k 1024 -t 4
```

Пример для прямоугольных матриц:

```bash
./main -m 600 -n 800 -k 400 -t 4
```

## Как работает параллельная версия

Строки результирующей матрицы `C` распределяются между потоками. Каждый поток
вызывает `multiply_rows` и записывает только в выделенный ему диапазон строк.
Поэтому потоки не изменяют одни и те же элементы и мьютекс не требуется.

Основной поток создаёт рабочие потоки функцией `pthread_create`, а затем
ожидает их завершения с помощью `pthread_join`.

## Ускорение и эффективность

Обозначения:

- `Tseq` — время последовательного алгоритма;
- `Tp` — время параллельного алгоритма с `p` потоками;
- `p` — число потоков.

Ускорение показывает, во сколько раз параллельная версия быстрее
последовательной:

```text
S = Tseq / Tp
```

Эффективность показывает, насколько эффективно используются потоки:

```text
E = S / p * 100%
```

Для точки с одним потоком в таблице и на графике используется время
последовательного алгоритма. Поэтому для неё `S = 1`, а `E = 100%`.

## Эксперименты для отчёта

Число логических ядер можно узнать командой:

```bash
sysctl -n hw.logicalcpu    # macOS
nproc                      # Linux
```

На проверенной системе доступно 10 логических ядер. Для отчёта проведены
опыты с последовательным алгоритмом и с 1, 4, 10 и 16 потоками:

```bash
./main -m 2048 -n 2048 -k 2048 -t 1
./main -m 2048 -n 2048 -k 2048 -t 4
./main -m 2048 -n 2048 -k 2048 -t 10
./main -m 2048 -n 2048 -k 2048 -t 16
```

Во всех опытах размеры матриц должны оставаться одинаковыми. Меняется только
число потоков. Для более устойчивых результатов каждый опыт рекомендуется
повторить несколько раз и использовать среднее время.

Результаты измерены на MacBook Air с 10 логическими ядрами. Размеры матриц во
всех опытах: `2048 x 2048`. В таблице приведены средние устойчивые значения;
аномальные запуски, вызванные посторонней нагрузкой системы, исключены.
Ускорение и эффективность рассчитаны относительно среднего времени
последовательного алгоритма `26992,798` мс. Точка с одним потоком приравнена к
последовательному алгоритму.

| Режим / число потоков | Время исполнения, мс | Ускорение | Эффективность, % |
|----------------------:|---------------------:|----------:|-----------------:|
| Последовательно       | 26992,798            | 1,000     | 100,00           |
| 1                     | 26992,798            | 1,000     | 100,00           |
| 4                     | 12258,728            | 2,202     | 55,05            |
| 10                    | 8561,194             | 3,153     | 31,53            |
| 16                    | 8656,933             | 3,118     | 19,49            |

При увеличении числа потоков до десяти время уменьшилось с `26992,798` до
`8561,194` мс. Наибольшее ускорение `3,153` получено при 10 потоках, что
совпадает с числом логических ядер проверенной системы. При 16 потоках время
немного выросло до `8656,933` мс, а ускорение снизилось до `3,118`.

Дополнительные потоки сверх числа логических ядер не добавляют вычислительных
ресурсов, но увеличивают расходы на создание, переключение и планирование.
Поэтому эффективность уменьшается с `55,05%` при 4 потоках до `31,53%` при 10
и `19,49%` при 16 потоках. Небольшие колебания результатов связаны с
кэш-памятью, изменением частоты процессора, планировщиком ОС и фоновой нагрузкой.
