# Лабораторная работа №3 — вариант 6

Реализация на C++ для macOS с использованием POSIX.
Дочерняя программа считает сумму целых чисел каждой строки входного файла.
Родительская получает суммы через общую память и выводит их в терминал.

## Сборка и запуск

Нужны `c++` и `make` из Command Line Tools для Xcode.
Команды выполняются из папки лабораторной: родитель запускает ребёнка по пути `./child`.

```sh
make
./parent tests/input.txt
```

Ожидаемый вывод:

```text
0
6
20
100
-10
0
4294967304
```

Для своего файла:

```sh
./parent "путь к файлу.txt"
```

Очистка собранных программ:

```sh
make clean
```

## Общая память

Родитель выполняет три шага:

1. `shm_open` создаёт именованный объект общей памяти и возвращает его дескриптор.
2. `ftruncate` задаёт размер объекта — `sizeof(SharedData)`.
3. `mmap` с флагом `MAP_SHARED` отображает объект в адресное пространство процесса.

В `mmap` передаётся именно дескриптор от `shm_open`.

В общей памяти хранится одна структура:

```cpp
struct SharedData {
    long long sum;
    State state;
};
```

| Состояние | Значение |
| --- | --- |
| `RESULT` | В `sum` находится очередная сумма |
| `FINISH` | Чтение файла закончено |
| `READ_ERROR` | Сообщение об ошибке чтения или запуска ребёнка |

Завершение определяется по `state`, поэтому ноль и отрицательные суммы
можно передавать как обычные результаты.

После успешного `execv` прежнее отображение ребёнка исчезает.
Программа `child` получает имена объектов через аргументы,
заново открывает общую память через `shm_open` и отображает её через `mmap`.
Вызов `close(memory)` после `mmap` закрывает дескриптор, но сохраняет отображение.

## Семафоры и порядок обмена

| Семафор | Начальное значение | Назначение |
| --- | --- | --- |
| `empty` | 1 | Разрешает ребёнку записать сообщение в свободную ячейку |
| `ready` | 0 | Разрешает родителю прочитать готовое сообщение |

Родитель создаёт семафоры через `sem_open` с `O_CREAT | O_EXCL`.
Ребёнок открывает существующие семафоры через `sem_open(имя, 0)`.
Этот `0` означает отсутствие флагов создания, а не сброс счётчика.

Передача одной суммы:

1. Ребёнок вызывает `sem_wait(empty)` и ждёт свободную ячейку.
2. Записывает `sum` и `state` в общую память.
3. Вызывает `sem_post(ready)`, разрешая родителю чтение.
4. Родитель выходит из `sem_wait(ready)` и выводит сумму.
5. Родитель вызывает `sem_post(empty)`, разрешая следующую запись.

`sem_wait` возвращает `0` при успешном ожидании, `-1` при ошибке.
Когда счётчик равен нулю, функция блокирует процесс до появления разрешения.
Постоянного опроса общей памяти нет.

После последней суммы ребёнок передаёт `FINISH`.
Родитель выходит из цикла получения сообщений и ждёт ребёнка через
`waitpid(pid, nullptr, 0)`. Код завершения ребёнка отдельно не проверяется.

## Имена и освобождение ресурсов

`make_name` формирует имена из префикса, буквы назначения и PID родителя:

```text
/l3m_12345 — общая память
/l3e_12345 — семафор empty
/l3r_12345 — семафор ready
```

У одновременно работающих родителей разные PID, поэтому имена различаются.
`O_EXCL` запрещает случайно открыть уже существующий объект вместо создания нового.

При штатном завершении ребёнок закрывает семафоры через `sem_close`
и убирает своё отображение через `munmap`.
Родитель после ожидания ребёнка делает то же самое, закрывает дескриптор памяти
и удаляет имена через `sem_unlink` и `shm_unlink`.

`munmap` убирает отображение только из текущего процесса.
`sem_close` и `close` закрывают доступ текущего процесса.
`sem_unlink` и `shm_unlink` удаляют имена объектов.
