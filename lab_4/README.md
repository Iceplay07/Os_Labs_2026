# ОС. Лабораторная работа №4 — вариант 6

**Язык:** C11. **ОС:** Linux или macOS.  
**Тема:** динамические библиотеки, связывание при сборке и загрузка во время исполнения.

## Контракты

```c
float sin_integral(float a, float b, float e);
float area(float a, float b);
```

| | libimpl1 | libimpl2 |
|---|---|---|
| `sin_integral()` | Метод левых прямоугольников | Метод трапеций |
| `area()` | Площадь прямоугольника `a*b` | Площадь прямоугольного треугольника `a*b/2` |

В обеих библиотеках экспортируются **одни и те же имена функций и сигнатуры**.

## Структура

```text
OS_Lab4_Var6/
```

## Сборка

Из корня проекта:

```bash
make
```

Получится папка `build/` с двумя библиотеками и двумя программами.

На **Linux** имена библиотек `libimpl1.so`, `libimpl2.so`. На **macOS** — `libimpl1.dylib`, `libimpl2.dylib`.

## Запуск

Из корня проекта:

```bash
make run1
make run2
```

Либо:

```bash
cd build
./program1
./program2
```

Важно: программа №2 использует относительные пути `./libimpl1.so` и `./libimpl2.so` (либо `.dylib`); поэтому запускайте её из `build/`. Команды `make run1/run2` переходят туда автоматически.

### Команды пользователя

- `1 A B e` — вычислить интеграл sin(x) на `[A,B]` с шагом `e`.
- `2 a b` — вычислить площадь по сторонам `a` и `b`.
- `0` — **только программа №2**, переключить текущую реализацию.
- `Ctrl+D` — завершить ввод (EOF).

Пример:

```text
$ make run2
Program 2: dynamic loading
Implementation 1: left rectangles and rectangle
Commands: 0 (switch) | 1 A B e | 2 a b | Ctrl+D to exit
2 3 4
Result: 12.000000
0
Switched to implementation 2
2 3 4
Result: 6.000000
```

## Сравнение методов подключения

**Программа №1:** код напрямую вызывает `sin_integral` и `area`. На этапе линковки записывается зависимость от libimpl1; динамический загрузчик ОС подгружает библиотеку до выполнения `main()`. В программе не нужно самостоятельно открывать библиотеку и приводить указатели функций.

**Программа №2:** программа не связана с libimpl1/libimpl2 при линковке. Во время исполнения `dlopen()` открывает файл, `dlsym()` находит адреса функций, а `dlclose()` снимает ссылку на библиотеку. Команда `0` загружает вторую библиотеку, получает функции, закрывает старую библиотеку и обновляет указатели.

Это **оба случая использования динамических библиотек**, а не сравнение статической библиотеки `.a` с динамической `.so`.

### Формулы

Для разбиения `[A,B]` на участки ширины `h_i <= e`:

- Левые прямоугольники: `I ≈ Σ sin(x_i) * h_i`.
- Трапеции: `I ≈ Σ (sin(x_i) + sin(x_(i+1))) * h_i / 2`.
- Точный ответ для контроля: `I = cos(A) - cos(B)`.

Последний неполный шаг обрабатывается корректно. Для обратных границ интегрирования знак меняется. Неверные аргументы возвращают `NAN` и приводят к сообщению об ошибке.

### Что показать при защите

1. `make` и содержимое `build/` — две динамические библиотеки и два исполняемых файла.
2. `make run1` + `2 3 4` → 12.
3. `make run2` + `2 3 4`, `0`, `2 3 4` → 12 и 6 без перезапуска.
4. `make run2` + `1 0 1 0.5`, `0`, `1 0 1 0.5` → разные значения интеграла.
5. `make test` — проходят проверки.

На Linux можно также показать `ldd build/program1` и `ldd build/program2`: у первой есть зависимость от `libimpl1.so`, у второй — нет. На macOS аналоги — `otool -L build/program1` и `otool -L build/program2`.
